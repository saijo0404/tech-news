# Spanner queues provide native transactional messaging

- **來源**: Google Cloud Blog Databases
- **發布日期**: 2026-10-03
- **原文連結**: https://cloud.google.com/blog/products/databases/spanner-queues-provide-native-transactional-messaging/

## 核心主題
Google 宣布 Spanner queues 的通用可用性，提供原生交易式訊息功能，專為可靠代理執行設計，解決 AI 代理在執行多步驟任務時需要維護內部狀態與發送異步動作之間的斷裂問題。

## 關鍵重點
- **原子化決定與行動入隊**：在單一 Spanner 讀寫交易中，代理可以同時更新內部狀態表並向同儕代理入隊任務，確保狀態變更與執行意圖作為單一原子單元提交。
- **預先排程執行與延遲**：隊列訊息可以立即發送或延遲發送，支援延遲重試、預排程代理檢查或 SLA 升級計時器等代理模式，無需外部 cron 排程器。
- **流式 SQL 拉取與任務管理**：自主代理使用流式 SQL 讀取任務，代理運行時可動態消費任務並在容量可用時處理，確保端到端任務執行狀態可靠性。
- **事件記憶持久化與交接**：代理記憶更新（包括長期事件摘要、反饋狀態轉換和子代理間上下文交接）可透過隊列異步且交易式地持久化，確保代理內部記憶與執行歷史完全同步。
- **交易式一次執行保證**：提供至少一次遞送和最多一次 ACK，實現恰好一次處理，確保代理工具呼叫結果、狀態修改、推理持久化和下游工具調用任務在單一交易中保存。

## 結論
Spanner queues 為自主代理提供堅固的交易式訊息基礎設施，將代理從數據推理到執行交易式動作无缝整合到單一統一平台中，特別適合需要可靠狀態管理與異步任務執行的代理工作負載。
