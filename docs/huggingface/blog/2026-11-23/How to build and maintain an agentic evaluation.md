# How to build and maintain an agentic evaluation

- **來源**: Hugging Face Blog
- **發布日期**: 2026-11-23
- **原文連結**: https://huggingface.co/blog/agentic-evals

## 核心主題
本文介紹了 AI 代理評估框架的開發流程、評估基準的演進以及開放源碼評估的重要性。

## 關鍵重點
- **評估演進的三個時代**：從問答時代（MMLU、GPQA）到代理時代（SWE-bench、WebArena），再到團隊/群體時代（評估多個代理協同工作）
- **代理評估的八個步驟**：定義主張→尋找任務→執行任務→調整任務→檢查評估→閱讀追蹤記錄→報告分數→比對模型
- **開放源碼評估的重要性**：98.2% 的評估分數由單一機構報告，開放源碼可促進更透明、可驗證的評估；Hugging Face Hub 已累積約 3500 個評估排行榜
- **公共審查的重要性**：可發現基準建構者遺漏的錯誤，如 Terminal-Bench 2.1 透過用戶報告修正了 28 個任務
- **常見失敗原因與修正**：分數檢查可能誤判、需測試分數器與參考解決方案、追蹤記錄可幫助識別失敗原因
- **策略性開放源碼**：平衡污染風險與開放需求，可公開任務規格與評估工具，應保護測試答案與私人數據
- **基準驗證的持續性**：發布後仍需持續驗證，專家審查發現 445 個基準存在構效度問題
- **改進建議**：明確定義所有參數與單位、使用合成數據確保參考答案可驗證、記錄完整追蹤記錄（ATIF 格式）

## 結論
建立和維護 AI 代理評估基準需要嚴謹的開發流程、透明的評估方法以及持續的驗證機制。開放源碼評估能促進更可靠的基準，但需平衡數據污染風險。
