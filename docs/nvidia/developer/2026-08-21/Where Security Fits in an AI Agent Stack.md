# Where Security Fits in an AI Agent Stack

- **來源**: NVIDIA Technical Blog
- **發布日期**: 2026-08-21
- **原文連結**: https://developer.nvidia.com/blog/where-security-fits-in-an-ai-agent-stack/

## 核心主題
這篇文章探討了 AI 代理堆疊中安全控制的適當位置，強調了行為控制與基礎設施控制的區別，以及如何在不同層級實施安全策略。

## 關鍵重點
- 安全控制應位於基礎設施層（如 NVIDIA OpenShell）而非可修改的 harness 邏輯層，以確保最終授權權限
- 採用最小權限、隔離、即時存取等傳統安全原則，並透過基礎設施層強制執行
- AI 代理堆疊包含五層架構：分佈/產品層、編排層（meta-harness）、代理 harness 層、安全運行時層、推理數據平面層
- 常見安全漏洞包括邊界不清、權限過剩、未受信任資料作為控制、外部效應失控等
- 建議建立四種安全配置文件：隔離型、連接型、生產型、對抗型，根據風險等級調整控制強度

## 結論
透過層級化安全模型，將行為控制（模型與 harness 層）與基礎設施控制（運行時與基礎設施層）明確分離，並確保所有行動都經過基礎設施層的政策檢查，可有效降低 AI 代理的安全風險並建立可審計的安全邊界。
