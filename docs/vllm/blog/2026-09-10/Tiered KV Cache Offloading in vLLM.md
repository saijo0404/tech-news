# Tiered KV Cache Offloading in vLLM

- **來源**: vLLM Blog
- **發布日期**: 2026-09-10
- **原文連結**: https://vllm.ai/blog/2026-09-10-tiered-kv-offloading

## 核心主題
vLLM 推出了分層 KV Cache 離線功能，透過將計算後的 KV 資料緩存在主記憶體、儲存系統與遠端節點之間，避免重新計算以節省資源並提升服務效率。

## 關鍵重點
- **主機導向設計**：所有 KV 資料透過主記憶體（CPU DRAM）流動，離線時從加速器移至主機，再傳遞至次級層級；重新載入時則逆向流程。
- **即時分配模式**：加速器記憶體在資料準備就緒後才分配，避免預留空閒時間，提升記憶體使用效率。
- **整合 I/O**：多加速器設定下，所有片段整合為單一共享主機記憶體區域，減少 I/O 操作次數，提升儲存與網路吞吐量。
- **標準化記憶體佈局**：主機區域使用標準化記憶體佈局，確保不同節點間可共享 KV 資料，無需重新映射或格式轉換。
- **簡單次級層級**：所有資料透過主機記憶體傳遞，使次級層級更容易建立與操作，使用標準 CPU 庫而非加速器 API。
- **三種次級層級**：
  - **檔案系統**：儲存 KV 片段為檔案，支援內容地址化命名，自動共享相同內容。
  - **物件儲存**：透過 NIXL 儲存至 S3 相容儲存，成本效益高且可跨實例共享。
  - **對等對等 (P2P)**：透過 ZMQ 與 RDMA 進行跨實例 KV 緩存共享，支援預填充/解碼分離與負載平衡。
- **混合模型支援**：支援混合記憶體分配器，將不同層級類型（如全注意力、滑動視窗、Mamba）統一為標準化 byte-buffer 表示。
- **可觀測性**：透過 Prometheus 指標提供主機緩存利用率、傳輸吞吐量、各層級延遲與命中率等數據。
- **效能提升**：隨著並發對話數增加（64-128 以上），儲存離線可將吞吐量提升兩倍以上，避免重新計算成本。

## 結論
vLLM 的分層 KV Cache 離線框架透過主機導向設計與多層級儲存策略，有效解決長上下文模型在加速記憶體不足時的重新計算問題，同時支援混合模型與跨節點共享，為大規模部署提供高效能與高擴展性的解決方案。
